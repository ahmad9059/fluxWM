## Edge cases to retain in upcoming work

1. **Configuration versus external effects:** a published generation may have a pending/failed companion. Inspect requested, observed and active autostart generations separately. Budget rejection retains old autostart ownership while logical settings remain applied; do not label that cross-process atomicity.
2. **Reload during child retirement:** an intermediate command may never execute. Restoring original argv must still replace a child already deliberately retired for a restartable identity. The process regression creates a real TERM interval to exercise this interleaving.
3. **Identity and history:** list positions change on insertion/removal; named IDs survive reorder. Once-only failed/exited commands must not silently retry. Removal releases argv but retains finite identity history; exhausting it must produce an error without partial process effects.
4. **Input and transactions:** held keys/buttons/grabs can defer publication indefinitely. Future keymap/output changes must preserve consumed releases, active grabs, focus, geometry and serial ownership, including outputless and host/native focus-loss states.
5. **Retained evidence:** build/profile changes can alter executable bytes. Hash final actual binaries and harnesses around runs; preserve exact raw console output. Source hashes, a reviewer report and test counts do not replace runtime execution evidence.
6. **Failure domains:** no generic `waitpid(-1)`, descendant cleanup or physical timing claim follows from owned-child or virtual-frame tests. Add separate oracles for each future claim.

The next implementation sequence should keep native ownership, transaction/window policy, desktop security and resource accounting visible alongside incremental configuration work. Earlier-phase blockers remain blockers when a later-phase component improves. Hardware/tool availability and release requirements must be recorded explicitly rather than assumed from this development machine.
