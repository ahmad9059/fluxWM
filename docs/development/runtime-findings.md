## What remains before a production window manager

No whole implementation phase is closed by these checks. The current artifact is a single-workspace, single virtual-output nested development compositor. The [phase gates](../10-roadmap.md) and [edge-case catalog](../15-edge-cases.md) remain the release authority; the complete catalogs must be executed against declared hardware/backend/build combinations.

The most immediate runtime blockers are full failure/native/transaction qualification of the new clipped scene, configure/ack/commit transaction ownership, full window-state/activation policy, popup/input conformance, host focus/key recovery, fairness and per-client resource accounting, and a bounded shutdown protocol. In particular an IPC quit acknowledgement can remain queued when the loop stops; the present fresh-connection smoke does not prove a saturated/pipelined quit reply drains. Clients must treat a lost quit reply as an ambiguous outcome and check instance lifetime. This is not yet a reliable acknowledged-shutdown contract.

Native DRM/seat/device/output lifecycle is absent. Multi-output hotplug/scale/transform, suspend/resume, GPU reset/allocator/sync behavior and actual presentation tracing require hardware execution. Lua parsing is implemented in a helper, but startup/config reload atomic application and last-good runtime state are not integrated. Animation/gesture clocks, overview, floating/fullscreen/maximize/minimize, rules, launch/session policy and workspace/output persistence remain incomplete.

Desktop capability work remains: clipboard/primary/DnD qualification, lock ownership and privacy barriers, capture permission/revocation, Xwayland, IME/text input, accessibility, activation/session integration and idle/power behavior. Advertising protocol source presence or a Smithay helper does not qualify these behaviors. Subscriptions, bounded pagination, pending-operation lifecycle and complete exit-history diagnostics remain IPC work.

Production operations still need target-matrix CI execution, reproducible packaging/installation, upgrade/rollback, native session entry and recovery, crash cleanup, structured bounded logs, dependency/security maintenance, fuzzing, resource exhaustion, long-running soak and documented support evidence. Local cached builds and hosted workflow configuration do not prove a clean-machine or hosted CI run.

## Shared scene and popup lifetime follow-through

Later implementation adds [shared composed scene geometry and input regions](runtime-scene.md), container-clipped root rendering and independently output-clipped popup rendering. Picking follows the last successful virtual render pass, with immediate liveness/mapped/ancestry/popup-membership eligibility checks. Input eligibility is not published after import/render failure. This is a foundation for transaction/native/animation ownership, not complete qualification of those features.

The [popup lifecycle fixture](popup-lifecycle-fixture.md) reproduces a missing non-grabbing popup dismissal after a processed parent unmap, then passes parent-unmap, invalid background grab with preserved foreground keyboard focus, and parent-role destruction after the fix. Authorized/nested grabs and deferred resource destruction/remap races remain open. Source-only rendering assertions are not substituted for those real-client observations.

Higher-owner/nested/offscreen popup scenarios and the full multi-device/grab matrix remain open. This evidence narrows the exact claim; it does not close the full input matrix.
