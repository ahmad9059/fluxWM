# Layout model implementation

`flux-layout` is a pure workspace model implemented from the FluxWM design. It has no Wayland, Lua, graphics, or device dependencies. This is incremental implementation evidence, not a phase 4 or phase 8 completion claim.

## Integration

Create `Layout::new(Size)` from the positive usable output dimensions, then insert mapped `WindowId` identities and validated `SizeConstraints`. `insert` explicitly activates the new window. Use `insert_with_focus(window, constraints, false)` when activation policy rejects a focus request; this preserves existing focus and camera. The first member of an empty workspace becomes focused so the nonempty-workspace invariant holds. Never insert untrusted protocol object IDs without the owning generational arena.

Use `placements()` for client target sizes. Its rectangles are in workspace world coordinates. Use `camera().rect_to_view(rect)` to build the scene in output-local logical coordinates. Apply the output usable-region offset, physical scale, output transform, surface offsets, and buffer conversions in the renderer. `visible_placements()` excludes offscreen content and hidden tabs. Offscreen members remain live; hidden tabs keep their allocated nonzero target size. `Placement::clip` is the world-space container clip; the renderer must intersect it with output/surface clips without replacing the target client size. `hit_test` accepts viewport-local logical coordinates and applies the container clip; the compositor must additionally apply input-region and surface-tree tests.

Focus through `focus_window` or `focus_direction`. Strip directional movement crosses columns horizontally and visits stack/tab members vertically. Canvas directional movement searches all eligible visible stack/active-tab members, including distant windows, using center-based half-plane/angular deviation, nonnegative projected edge distance, perpendicular center distance, and stable window ID. Hidden tabs require explicit `cycle_tab(forward)` or direct focus rather than spatial navigation. Focus reveals content using minimum camera motion; oversized content aligns its leading edge. `join_column` moves a window without duplicating membership. `move_focused` reorders columns/members in strip mode and moves 32 logical units in canvas mode.

Stack allocation starts at each client's minimum height and distributes remaining height equally while respecting maxima. If minimums overflow, each member retains its minimum and focusing scrolls the internal column to reveal it. Tab mode presents only the active member. Column width policies support fixed logical widths and viewport fractions. Widths of unrelated columns are never reduced to fit the output. A client maximum can leave blank space within its column; maximum widths do not force other clients to violate their minima.

Each column owns a workspace-local stable `GroupId`, shared membership/order, active member, and stack/tab policy. Canvas groups own independent world rectangles and internal overflow offsets; strip columns retain their own width policy and overflow offset. `group_for(window)` resolves identity and `canvas_groups()` reports group geometry; `set_canvas_group_rect(group, rect)` moves/resizes the whole group. The existing `set_canvas_rect(window, rect)` is a compatibility alias for the containing group, so moving one tab moves its group. Joining moves membership into the destination group and deletes an empty source group. Closing a group representative cannot invalidate a still-live group ID. IDs increase monotonically, are never reused within a layout, and must be paired with workspace identity externally.

On the first transition into canvas, group geometry is seeded from the **current** strip widths, order, usable height, and local overflow offset, including mutations made after insertion. The first return to strip sorts groups by world x, y, then stable group identity while retaining width policies. Explicit initialization/conversion flags make this a one-time conversion. Later transitions preserve independent canvas geometry and both mode cameras exactly; they do not silently refocus/reveal and overwrite saved cameras. A later explicit focus action performs reveal/recovery. Shared group membership/tab mode changes remain effective in both modes. New groups after initialization seed from current strip order or adjacent to the active canvas group; existing canvas groups stay fixed. Canvas has independently movable x/y world coordinates, negative placement, independent camera zoom, and inverse picking. `rebase_canvas` moves every canvas member and its camera atomically. The caller must apply the same delta to any external animation endpoints, gesture anchors, spatial indices, and accumulated-origin record before presenting again.

Runtime reloads can use `reconfigure(gap, mode) -> Result<(), LayoutError>` to prepare and publish logical gap/mode changes atomically. It clones the model, applies changed gaps and the existing one-time mode conversion rules, then checks aggregate strip extent, membership/focus/cameras, and placement/container geometry in both saved modes before replacing the original. Any error preserves the full original model, including dormant geometry and conversion state. Membership, window/group IDs, active tabs, focus, and existing width policies survive successful reloads; a changed gap reveals focus in the previously active mode, while unchanged gaps preserve saved cameras during mode restoration. `gap()` exposes the current value for diagnostics. This API has no protocol effects and does not change the default width for future admissions; the runtime owns that policy and cross-workspace/config publication. The model currently accepts gaps from 0 through 1024 inclusive, whereas the config schema accepts through 4096; runtime candidate preparation must reject unrepresentable values before publishing a config.

## Input and capacity policy

Invalid, nonfinite, zero-size, conflicting min/max, and out-of-range inputs return typed errors. `SizeConstraints::from_xdg((min_w,min_h),(max_w,max_h))` adapts independently unconstrained zero axes, normalizes zero minima to one, and rejects negative/conflicting or unrepresentable minima. Finite maxima above the implementation size ceiling are bounded to that ceiling; this adapter does not replace protocol validation. Empty usable regions retain the last valid layout. Logical sizes and coordinate magnitudes are bounded by `MAX_COORD` (one billion logical units). Strip mutations reject widths whose combined extent exceeds that bound, before changing state. This is a finite precision safeguard, not a hardware qualification limit or claim of infinite physical storage. Explicit rebasing supports long-range canvas navigation; the compositor still needs its checked accumulated-origin representation.

Membership is unique in column lists, constraints, canvas geometry, and focus history. Removing an active member chooses the latest live history entry, then a deterministic neighbor; closing the last member resets both cameras. `validate()` checks cross-representation membership, focus, active tabs, nonzero finite geometry, and cameras and is available to replay harnesses.

## Verification and remaining work

The crate tests independent-width scrolling with 20 members; oversized stack minimums and internal reachability; tabs and tab close; maximum-height redistribution; real negative/two-axis canvas positions and mode restoration; transform inversion and large-coordinate rebasing; rejected mutations; generational identity separation; deterministic spatial focus; first-conversion seeding and stable sorting, subsequent camera preservation, stable group IDs after member close, canvas tab visibility, group clipping/overflow reachability, edge-distance focus scoring, independent unconstrained XDG axes, and a 10,000-command replay that checks membership, focus, and geometry after every command.

Run `cargo test -p flux-layout` and `cargo clippy -p flux-layout --all-targets -- -D warnings` from the workspace root.

Remaining production work includes multi-workspace/output ownership and migration; floating/dialog layers; fullscreen/maximized/minimized state and backdrop policy; configure transactions and stale-buffer handling; compositor activation policy integration; canvas overlap resolution and persistent stacking policy; gestures and snap hysteresis; overview/search UI and accessibility; weighted stack heights; output fractional/physical shared-edge rounding; viewport resize compatibility with stale client buffers; cached/binary-search visibility and measured spatial-index thresholds. Current scene queries allocate and scan all members, so no O(log n + k) performance claim is made. Pure model tests do not establish real-client, GPU, output hotplug, or phase gate qualification.

[Runtime width defaults](config-widths.md) now copy a configured fixed/fraction policy into each new admission. `reconfigure_with_default_width` validates and publishes it atomically with gap/mode while preserving existing column policies. `reconfigure` retains the current default for existing callers. Viewport changes must keep the default resolvable; rejected admissions preserve all current state.
